# Security Review Memo: Trust Gate Metadata

**Feature**: 011-trust-gate-framework
**Date**: 2025-10-11
**Owners**: Trust Gate Governance WG · Security Engineering Liaison
**Related Docs**: `specs/011-trust-gate-framework/{plan.md,research.md,data-model.md,quickstart.md}`, `docs/governance/retention_policy.md`, `docs/operations/trust_gates.md`

## 1. Scope & Context
- Trust gate artifacts produced by `poetry run trust-gates` (reports, diagnostics, vendor metadata, signatures).
- SQLite persistence (`trust_gate_suites`, `trust_gate_results`) and manifest extensions containing gate outcomes.
- Benchmark payloads generated by `scripts/bench/perf_run.py` that substantiate runtime waivers.
- Detached signatures (.sig) required for governance attestations and CI gating.

Assumptions: AlphaForge Brain executes on controlled build agents with encrypted disks; signing keys managed via Key Vault integration (refer to `infra/keyvault/trust_gates.tf`).

## 2. Data Classification
| Artifact | Classification | Rationale | Handling Requirements |
|----------|----------------|-----------|------------------------|
| `trust_gate_report.json` | **Confidential** | Contains baseline hashes, configuration digests, waiver references. | Store in Git-ignored artifact bucket; encrypt at rest; restrict to validation & governance groups. |
| Gate diagnostics (`gate_*_diagnostics.json`, `timezone_trace.parquet`) | **Confidential** | May include vendor dataset signatures, symbol lists, timestamp traces. | Keep under `artifacts/trust_gates/reports/{run_id}/`; deny public replication; scrub PII before sharing externally. |
| `ingest_vendor_metadata.json` | **Restricted** | Includes vendor version strings, API endpoints, rate-limit telemetry. | Mask vendor credentials; rotate access logs per retention policy (§4). |
| Detached signatures (`trust_gate_report.sig`) | **Internal** | No sensitive payload, but tampering would undermine attestations. | Store alongside report; validate checksum before waiver approval. |
| SQLite tables (`trust_gate_suites`, `trust_gate_results`) | **Confidential** | Mirror report contents with run linkage. | Database backups must inherit encryption and RBAC controls. |
| Benchmark payloads (`zz_artifacts/perf_latest.json`) | **Internal** | Runtime metrics only; required for waivers. | Retain 12 months; ensure metrics server redacts run IDs if shared. |

## 3. Storage & Access Controls
- **Artifacts**: Retained on build agent filesystem + S3-backed artifact vault with default SSE-KMS encryption. Upload path mirrors `artifacts/trust_gates/reports/{run_id}/`.
- **Database**: SQLite lives on runner; nightly export to encrypted blob storage governed by existing Masters validation backup job.
- **Manifests**: Continue storing in `artifacts/manifests/`; trust gate block inherits existing ACLs.
- **Secrets**: Signing key retrieved at runtime via `AF_TRUST_GATES_SIGNING_KEY` environment variable, loaded from Key Vault; never persisted to disk.
- **Access**: RBAC ensures only Validation WG, Security, and Governance roles receive read access to trust gate bucket prefixes; CI agents use short-lived credentials rotated nightly.

## 4. Retention & Disposal
Align with `docs/governance/retention_policy.md` (2025-10-11 revision):
- Reports + signatures: retain **3 years**.
- Diagnostics + vendor metadata: retain **18 months** (or shorter if vendor contract mandates); purge via scheduled lifecycle rule and log deletion.
- Waiver artifacts (including benchmark payloads tied to runtime waivers): retain **12 months** post-expiry.
- SQLite exports: align with manifests (minimum **18 months**); sanitize older than 36 months.

Destruction must use cryptographic erase for KMS-backed storage and document completion in governance tracker.

## 5. Threat Assessment
| Threat | Impact | Likelihood | Mitigation |
|--------|--------|------------|------------|
| Unauthorized access to vendor metadata revealing integration details | Medium | Low | Enforce per-prefix IAM, redact tokens, monitor access logs. |
| Baseline tampering leading to false pass | High | Low | Detached signatures, manifest hash linkage, CI verifies signature with trusted public key. |
| Artifact exfiltration via compromised CI agent | High | Medium | Harden agents (no interactive logins), run agents inside isolated VNet, enable Defender alerts. |
| Stale waivers or artifacts retained beyond policy | Medium | Medium | Automated lifecycle policies + governance review checklists. |
| Replay attacks against signature verification | Medium | Low | Include run ID + timestamp inside signed payload; require nonce in waiver tooling. |

## 6. Controls & Operational Playbook
1. **Signing Workflow**
   - Load signing key from Key Vault at suite start; delete from memory post-signing.
   - Embed `signature_version` and `signing_key_id` into report metadata.
   - Validation WG verifies signature before approving waivers.
2. **Audit Logging**
   - Structlog emits `security_event="trust_gate_artifact_write"` with SHA256 and storage path.
   - Metrics export `trust_gate_artifacts_written_total` labeled by gate for anomaly detection.
3. **Baseline Regeneration**
   - Governance change request required; record signer identity and commit hash in `baseline.signature` per research §2.
   - Store diff between previous and new baseline in encrypted appendix (see TODO below).
4. **Incident Response**
   - Security severity matrix: baseline tampering or signature mismatch = Sev2; vendor metadata leak = Sev3.
   - Playbook references `docs/dev/incident_response.md` with trust gate specific contact list appended.
5. **Waiver Attachments**
   - Runtime waivers must include `zz_artifacts/perf_latest.json` alongside signed reports (per WAIVERS.md update) and be stored within same encrypted vault.
